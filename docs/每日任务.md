下面按你们文档里的设定来拆：**3 个人、11 天、GoLiteConfig 轻量级分布式配置中心**。

我先给三个人固定角色：

- **成员 A：后端核心负责人**
  负责 Go 服务端、Etcd 封装、API、Watch、SDK 核心逻辑。
- **成员 B：部署与演示负责人**
  负责 Docker Compose、启动脚本、curl/Postman、演示流程、录屏环境。
- **成员 C：文档与测试负责人**
  负责 API 文档、测试用例、README、需求/设计/测试报告、协助 demo。

## 第 6 天：回滚接口 POST /api/config/rollback

| 成员 | 今日任务                                               | 产出物            | 审核标准                                               |
| ---- | ------------------------------------------------------ | ----------------- | ------------------------------------------------------ |
| A    | 实现回滚逻辑：读取目标版本，复制成新版本，更新 current | rollback 接口     | 回滚到 v1 后不是 current=v1，而是生成 v3/v4 这类新版本 |
| B    | 准备演示脚本：发布 v1、发布 v2、回滚 v1                | rollback 测试命令 | 一套命令能完整演示回滚                                 |

请求：

```
{
  "app": "order-service",
  "env": "prod",
  "target_version": "v1",
  "publisher": "admin",
  "comment": "回滚到 v1"
}
```

**当日验收：**

```

## 第 7 天：长轮询 Watch 接口

| 成员 | 今日任务                                                     | 产出物         | 审核标准                                                     |
| ---- | ------------------------------------------------------------ | -------------- | ------------------------------------------------------------ |
| A    | 实现 `/api/watch`；根据 last_revision 判断是否有变化；无变化最多等待 60 秒 | Watch 接口     | 有变化立即返回 200；无变化超时返回 304；多个客户端可同时等待 |
| B    | 准备两个终端演示流程：一个 watch，一个发布配置               | Watch 演示命令 | 发布配置后，watch 请求能立刻返回                             |
| C    | 记录 Watch 行为说明和测试结果                                | Watch 文档     | 明确 200、304、超时、错误场景                                |

接口：

```
GET /api/watch?app=order-service&env=prod&last_revision=128
```

**当日验收：**

```
1. 客户端 last_revision 旧于服务端，立即返回最新配置。
2. 客户端 last_revision 等于服务端，连接挂起等待。
3. 发布新配置后，挂起请求被唤醒。
4. 超过等待时间无变化，返回 304。
```

SDK 接口建议：

```

    Get(key string) (string, error)
    GetJSON(key string, target any) error

}
```

```

## 每日通用审核清单

每天结束前，三个人一起过这 6 项：

```
1. 今天的功能能不能运行？
2. 有没有可复现命令？
3. 有没有对应文档？
4. 有没有异常情况测试？
5. 有没有影响明天任务的阻塞？
6. 今天产出是否提交到对应分支？
```

建议每天留 15 分钟做小结：

```
A：今天后端完成了什么，明天卡点是什么
B：今天部署/演示完成了什么，还缺什么命令
C：今天文档/测试覆盖了什么，哪些接口还没测
```

## 阶段性审核节点

**第 2 天结束：基础环境验收**

```
Etcd 可启动
server 可启动
/health 可访问
```

**第 4 天结束：CRUD 初步验收**

```
能发布配置
能查询配置
Etcd 中 Key 结构正确
```

**第 6 天结束：版本能力验收**

```
能查看历史版本
能回滚
回滚会生成新版本
```

**第 8 天结束：Watch + SDK 验收**

```
watch 能返回变化
SDK 有本地缓存
SDK 能自动监听变化
```

**第 11 天结束：最终交付验收**

```
完整演示链路跑通
文档齐全
报告/PPT/录屏准备完成
```

最关键的是：你们不要每天都“写了一些代码但没人知道能不能跑”。每天必须有一个可执行命令、一个可观察结果、一个明确审核标准。这样项目不会到最后两天才发现主链路没打通。
