## 一、项目概述

### 1.1 项目背景

在微服务架构中，应用配置（数据库地址、Redis 连接、限流阈值、功能开关等）往往分散在各个服务的本地文件或环境变量中。一旦需要修改，通常要重新打包、发版、重启，效率低且容易出错。

**GoLiteConfig** 旨在基于 **Etcd** 构建一个轻量级配置中心，实现：

- 多环境（dev / prod）配置集中管理
- 配置变更后客户端 **热加载**，业务服务 **无需重启**
- 配置 **版本管理** 与 **回滚**
- 提供 **HTTP 管理 API** 与 **Go 客户端 SDK**

本项目对标 Nacos、Apollo 等商业产品的 **核心能力子集**，作为团队实训与作品展示项目。

### 1.2 项目目标

| 目标类型 | 描述 |
|----------|------|
| **功能目标** | 完成配置发布、查询、删除、长轮询监听、热加载、版本回滚的最小可用链路 |
| **展示目标** | 可通过终端演示「改配置 → 业务服务自动更新 → 回滚恢复」完整流程 |
| **学习目标** | 掌握 Etcd 集成、HTTP API 设计、长轮询/Watch、Go SDK 与 Docker 部署 |
| **交付目标** | 可运行代码 + Docker Compose + 演示脚本 + 项目文档 |

### 1.3 不在初版范围内（明确排除）

以下功能 **不做**，避免范围蔓延：

- Web 管理控制台（UI）
- 用户权限 / 登录鉴权
- 配置加密（Vault / AES）
- 多语言 SDK（Java、Python 等）
- 多数据中心同步
- 完整生产级高可用（3 节点 Etcd 集群可作为拓展说明，初版单节点即可）

## 二、用户与使用场景

### 2.1 目标用户（角色）

| 角色 | 说明 | 使用方式 |
|------|------|----------|
| **运维 / 开发人员** | 发布、查询、回滚配置 | 调用 HTTP API（curl / Postman） |
| **业务微服务** | 读取配置并监听变更 | 集成 Go SDK |
| **评审 / 答辩老师** | 查看项目成果 | 阅读文档 + 观看演示 |

### 2.2 核心使用场景

#### 场景 1：发布配置

运维为 `order-service` 的 prod 环境发布数据库连接配置：

```
POST /api/config
→ 配置写入 Etcd
→ 所有监听该应用的客户端收到变更
```

#### 场景 2：配置热加载

业务服务启动后集成 SDK，运维修改 Redis 地址：

```
业务进程不重启
→ SDK 后台监听到变更
→ 更新本地缓存
→ 触发回调，打印/应用新配置
```

#### 场景 3：版本回滚

运维误改生产配置，需要回滚到上一版本：

```
POST /api/config/rollback
→ 读取历史版本内容，发布为新版本
→ 客户端自动恢复到旧配置值
```

#### 场景 4：降级容错

Etcd 短暂不可用时，SDK 使用本地缓存继续运行，并记录错误日志。

### 3.2 配置存储需求（FR-02）

#### Key 路径规范

```
/config/{app}/{env}/{version}/{group}/{key}
```

**示例：**

```
/config/order-service/prod/v1/database/host     → "192.168.1.10"
/config/order-service/prod/v1/database/port     → "3306"
/config/order-service/prod/v1/redis/addr      → "127.0.0.1:6379"
```

#### 元数据 Key

每次发布版本时，额外写入元数据：

```
/config/{app}/{env}/_meta/{version}
```

元数据内容（JSON）：

```json
{
  "version": "v2",
  "revision": 128,
  "publisher": "admin",
  "comment": "切换 Redis 节点",
  "created_at": "2026-06-29T10:00:00Z"
}
```

#### 支持格式

- JSON（必须）
- YAML（可选，P1）

### 3.3 管理 API 需求（FR-03 ~ FR-09）

#### FR-03 发布配置

```
POST /api/config
Content-Type: application/json

{
  "app": "order-service",
  "env": "prod",
  "group": "database",
  "key": "host",
  "value": "192.168.1.10",
  "comment": "初始化配置"
}
```

**响应：** 201 Created，返回 version、revision。

#### FR-04 查询配置

```
GET /api/config?app=order-service&env=prod&group=database
```

**响应：** 该分组下所有 key-value 列表。

#### FR-05 删除配置

```
DELETE /api/config?app=order-service&env=prod&group=database&key=host
```

#### FR-06 长轮询监听

```
GET /api/watch?app=order-service&env=prod&last_revision=100
```

**行为：**

1. 若 Etcd revision > last_revision → 立即返回最新配置（200）
2. 若相等 → 挂起等待，最长 60 秒
3. 期间有变更 → 被唤醒并返回（200）
4. 超时无变更 → 304 Not Modified

#### FR-08 版本回滚

```
POST /api/config/rollback

{
  "app": "order-service",
  "env": "prod",
  "target_version": "v1"
}
```

**行为：** 读取 v1 的全部配置，作为新版本 v3 重新发布（保留审计链）。

#### FR-09 版本对比

```
GET /api/config/diff?app=order-service&env=prod&v1=1&v2=2
```

**响应：** 两个版本之间的增删改差异。

### 3.4 客户端 SDK 需求（FR-10 ~ FR-12）

#### 接口定义

```go
type ConfigProvider interface {
    Get(key string) (string, error)
    GetJSON(key string, target interface{}) error
    Watch(ctx context.Context, onChange func(event ConfigChangeEvent)) error
    Close() error
}
```

#### 行为要求

| 行为 | 要求 |
|------|------|
| 启动拉取 | 首次连接时拉取全量配置到本地缓存 |
| 后台监听 | 独立 goroutine 长轮询 /api/watch |
| 变更回调 | 收到变更后更新缓存，调用 onChange |
| 降级 | Etcd/服务端不可用时，Get 仍返回缓存值，并打 Warn 日志 |

### 3.5 示例程序需求（FR-13）

路径建议：`examples/demo-service/main.go`

**演示行为：**

1. 启动时打印当前全部配置
2. 注册 Watch 回调
3. 配置变更时打印：`[热更新] database.host: 旧值 → 新值`
4. 日志带颜色或明确前缀，方便答辩投屏

## 九、验收标准（Definition of Done）

### 9.1 功能验收

- [ ] `docker compose up -d` 后 Etcd 与服务端正常
- [ ] POST /api/config 发布配置，Etcd 中 key 正确
- [ ] GET /api/config 能按 app/env/group 查询
- [ ] demo-service 启动后打印当前配置
- [ ] 修改配置后 **5 秒内** demo-service 打印变更（**不重启**）
- [ ] rollback 后 demo-service 恢复旧值
- [ ] README 中他人可按步骤复现演示

### 9.2 演示验收（答辩场景）

**三窗口演示流程（≤ 5 分钟）：**

1. 启动：`docker compose up -d` + `go run examples/demo-service`
2. 发布配置 v1 → demo 打印初始值
3. 发布配置 v2 → demo 打印热更新
4. 回滚到 v1 → demo 恢复
5. （可选）停止 Etcd → demo 仍可读缓存
